# 项目库卡片

用于把已核验的项目资料整理成项目库导入格式。项目库 skill 统一使用本目录，不再拆分出第二个同类 skill。

## 工作流程

1. 先阅读项目库 JSON schema，再编写或修复卡片。
2. 检查工作仓库中已有的项目库 JSON，沿用已验证的字段结构，不凭空增加字段。
3. 输出一个 JSON 数组；每个数组元素对应一个项目。
4. 除非明确要求发布，否则保持 `isPublished: false`。
5. 导入前运行 `jq empty <file>`，并检查必填字段、数字范围和图片链接。

## 内容边界

- `cases` 只放展示案例；外部小红书或店铺案例使用 `type: "external"`。
- `resources` 放学习资料；内部内容默认放在 `resources`，除非明确要求展示为案例。
- 只写来源能够支持的粉丝量、价格、销量、收入和时间范围；缺失信息应省略或明确标注未知。
- 不把累计 GMV 写成月收入或净利润，必须区分营收、GMV、毛利和利润。
- 保留来源、作者、原文链接和外部 ID，不改写为未经核验的结论。

## 卡片字段要求

必须包含：`worth_reason`、`revenue_model`、`income_estimate`、`action_guide`。

`incomeMin` 与 `incomeMax` 必须是数字，且 `incomeMax >= incomeMin`。`summary` 是导入器展示的项目简介，长度不超过 60 个字符。

`externalId` 只使用用户或项目系统提供的值；历史导入格式中应按字符串保存。`platformMenuIds`、`monetizeMenuIds`、`crowdMenuIds` 使用已验证的数字 ID 数组，不使用标签名或猜测的 ID。

## 案例标题

外部案例标题优先使用证据导向的紧凑句式：

`主体/店铺名：粉丝量，主卖/主做什么，代表性商品或服务的价格“商品名”已售 X 单`

如果来源没有对应字段，就省略该部分；不得补写推测数字。

## 图片与链接检查

- `images` 和案例图片必须是导入器可访问的 URL。
- 禁止使用本地路径、`file://` URI 或猜测的链接。
- 导入前逐个检查图片 URL；缺少可访问图片时停止交付并说明缺口。
- 不要为了“完整”虚构 `url`、`link` 或其他字段。

## 验收命令

```bash
jq empty <project-card.json>
```

同时人工确认必填字段存在、收入范围有效、菜单 ID 类型正确、来源可追溯，以及所有图片链接可访问。
