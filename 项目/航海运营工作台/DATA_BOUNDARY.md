# 航海运营工作台数据边界

## 当前数据源

工作台当前只使用生财 MCP 的只读数据。群聊 ZIP、原始 CSV/JSONL、本地 SQLite、Hermes 日志和历史演示数据均不进入当前快照或页面。

允许的项目级聚合包括：

- 项目名称、类型、方向、目标、状态和时间节点；
- 任务标题、开放时间、建议完成时间和提交窗口；
- 最近 24 小时新增问题数；
- 尚无首答的问题数、超过 48 小时尚无首答的问题数；
- 固定主题分类下的匿名问答计数；
- 项目数量、数据时间、采集覆盖和 MCP 工具状态；
- 由任务时间与首答时效产生、仍需人工确认的运营建议。

总报名、总作业、未点评总量、点评覆盖、人均作业和平台 `questionStatus` 不再作为页面运营指标。提交次数不能推导完成率、独立完成人数或掉队人数。

## 明确禁止公开

- 成员姓名、头像、账号、联系方式和任何用户 ID；
- 作业标题、正文、预览、图片、链接和来源 ID；
- 问答标题、正文、回答、评论和来源 ID；
- 群名、群聊原文、消息 ID、文件 Key 和证据编号；
- ZIP、CSV、JSONL、SQLite、环境变量、Token、Cookie 和凭证；
- 未经核验及授权的个人案例或“航海好事”。

同步写入 D1 前和公开 API 返回前都必须执行同一套显式字段白名单投影，不能依赖禁止字段黑名单，也不能直接转发输入 JSON。当前运行链路只使用 `scys_ops_snapshots` MCP 专用表；历史群聊聚合表仅作为不可见备份保留，Worker 与同步脚本均无读取路径。

## 航海好事

当前任务制作业没有经过验证的 `good/S 级 good` 映射。作业数量、关键词命中、点赞或评论都不能直接替代“航海好事”。页面只展示项目级成果聚合；个人好事需经过证据核验、匿名化、本人或运营授权后，进入独立的公开投影。

人工流转固定为：`候选发现 -> 待运营看稿 -> 需船员修改 -> 运营复看 -> 待同步精华修改 -> 后续处理中 -> 已完成 / 本轮不推进`。运营是唯一内容判断人，领队和志愿者只负责传达。

## 新鲜度与失败状态

- 页面同时显示 MCP 拉取时间和上游数据时间。
- 问答时效按 `createdAt` 和 `answerCount` 计算，不直接采用长期未闭合的 `questionStatus`。
- 主题只使用受控分类码和计数，不公开问题标题、正文或自由文本摘要。
- 超过健康阈值的快照必须标记为陈旧，不得只因数据库中仍有项目就显示正常。
- 部分结果、工具失败或数据边界必须在 `sourceChecks` 和页面中明确呈现。
- MCP 拉取失败时保留最后一次快照用于排查，但必须标记失败或陈旧，不能称为最新数据。

## 写入边界

公开 Worker 只读，不提供确认、修改、指派、发布或导入接口。ZIP/群聊同步脚本已永久停用。负责人、截止时间、处理状态与人工确认记录应放在受保护的内部运营服务中，而不是公开网站。
