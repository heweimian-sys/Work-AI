# 航海情报更新流程

网站只读取 `public/content/` 中已经人工审核的内容。群聊原始消息、未确认结论和审核草稿不会直接展示给船员。

每日更新顺序：

1. 使用生财 MCP 按 4 个目标群和上次 `coveredUntil` 之后的时间增量拉取。
2. 原始结果保存到 `content/raw/YYYY-MM-DD.json`，保留消息 ID、群名、发送人和时间，便于去重与追溯。
3. 清除系统提示、拍一拍、表情回复、重复通知和无有效信息的短消息。
4. 建立提问—回答—助教/教练确认关系，生成 `content/drafts/YYYY-MM-DD.json`。
5. 人工逐项检查行动结论、适用条件、来源群和时间；审核人填写 `reviewedBy`，将 `reviewStatus` 改为 `approved`。
6. 执行 `pnpm content:publish -- content/drafts/YYYY-MM-DD.json`。校验通过后，同时生成当天归档和 `latest.json`。
7. 构建网站并检查今日概览、答疑、往期入口和分享图片。

## 固定更新规则

- 工作数据每 30 分钟按四个群各自的最后消息时间增量拉取，并按 `msgId` 去重；不重复扫描整段历史。
- 公开版计划在每天 12:00、18:00、22:30 三次人工审核后更新。紧急时间变化、入口失效和规则变化优先插入。
- 先高召回：能提供事实、答案、操作、限制条件、失败经验、实操方法或结果的消息，即使只出现一次也进入候选池。
- 再聚类：栏目由当天真实讨论生成，不预设每天必须出现哪些问题。同一事件的提问、追问、回答、反例与验证必须合并。
- 删除项仅限无行动价值内容：收到、已预约、表情、拍一拍、纯寒暄、无新增信息的重复转述。
- 助教或教练明确回答可写为“已确认”；船员经验写明是谁做过和适用条件；没有验证的观点只进入审核区，不直接发布。
- 分享长文与网站使用同一份章节数据生成，不能另做一份五点摘要；图片分享包按章节逐张导出。

发布脚本会拒绝未审核草稿，以及缺少来源、结论或行动步骤的内容。`content/schema.json` 是编辑器和后续自动提炼程序共用的数据契约。
